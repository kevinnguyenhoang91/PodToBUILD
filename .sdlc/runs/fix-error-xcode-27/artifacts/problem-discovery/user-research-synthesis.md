# User Research Synthesis

**Agent:** sub-user-research-synthesizer · **Phase:** 0

## Affected Users

| Segment | Size / signal | Pain | Severity |
|---|---|---|---|
| PodToBUILD maintainers on macOS 27 | Anyone who upgrades Xcode; upgrade is effectively mandatory over time | Cannot build, test, or cut a release. `make build`, `make unit-test`, `make release`, `make build-test` all fail. | **Blocker** |
| Downstream `rules_pods` consumers | Consume the `PodToBUILD.zip` release artifact (prebuilt `bin/Compiler`, `bin/RepoTools`) | Indirect — releases cannot be produced, so bug fixes stop flowing. | High |
| CI | `.github/workflows` (has `workflow_dispatch`, per commit 90cc3b9) | Red on any macOS-27 runner image. | **Blocker** |

## Evidence

1. **Direct reproduction** on this host — full failure captured in `problem-statement.md`.
2. **Binary forensics** — `otool -l` confirms 0 `LC_UUID` load commands on the three
   `_compile_cc_file`-generated binaries; `xcode-locator-bin` (generated by a different code
   path with no `-no_uuid`) has 1 and works.
3. **Causal proof** — recompiling `wrapped_clang.cc` from Bazel's own embedded source with the
   identical command line minus `-Wl,-no_uuid` produces a binary with `LC_UUID=2` that dyld
   loads (it reaches the program's own argv[0] check). Dropping it into `local_config_cc`
   turned a hard `FAILED` into `INFO: Build completed successfully, 44 total actions`.
4. **Residual defect confirmed** — with only `wrapped_clang` patched, the build succeeds but
   still emits four `dyld: missing LC_UUID ... libtool_check_unique` / `Abort trap: 6` messages.
   This is the silent-degradation case: `external/local_config_cc/libtool` line 52 does not
   propagate the failure, so duplicate-symbol checking is quietly skipped.

## Why this is not "just wait for an upgrade"

The defect lives in the Bazel **binary committed to this repo** (`tools/bazel`, 6.3.2). Nothing
the user can install fixes it without changing the pinned Bazel version — and that pin is load-
bearing (`TESTED_BAZEL_VERSION=6.3.2`, rules_apple 1.1.3 from 2022, WORKSPACE-mode only).

## Frequency
100% of builds on macOS 27. Not flaky, not environment-specific beyond the OS major version.
